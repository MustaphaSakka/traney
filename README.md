# TRANEY

**Traney (Transfer Money)** is a Go REST API for managing clients, accounts and money transfers.

The project is built around a **Hexagonal Architecture (Ports & Adapters)** to keep business logic independent from infrastructure and external dependencies.

## Architecture

The project is organized into the following layers:

```text
traney/
├── app/          # HTTP handlers, routes and application bootstrap
├── domain/       # Business entities, repositories and core logic
├── dto/          # Data Transfer Objects
├── service/      # Application/business services
├── mocks/        # Generated mocks used by tests
├── resources/    # Database initialization / resources
├── main.go       # Application entry point
└── ...
```

### Main principles

* Hexagonal Architecture
* Separation of business logic and infrastructure
* Repository pattern
* Dependency inversion
* Unit testing with generated mocks
* JWT-based authentication
* Environment-based configuration

## Requirements

* Go 1.22+
* MySQL 8+
* Git
* `traney-auth` running for authenticated API access

The project has been tested with Go `1.27.x`.

## Configuration

Create a `.env` file at the root of the project:

```env
DB_USER=root
DB_PASSWORD=root
DB_HOST=localhost
DB_PORT=3306
DB_NAME=traney
```

A `.env.example` file should be committed to the repository, while `.env` must remain ignored by Git.

The application loads the environment configuration at startup.

## Database

The application uses MySQL.

The database must contain the required tables:

* `clients`
* `accounts`
* `users`

Database initialization scripts are available under `resources/`.

## Installation

Clone the repository:

```bash
git clone https://github.com/MustaphaSakka/traney.git
cd traney
```

Download dependencies:

```bash
go mod download
```

Generate the test mocks:

```bash
./generate-mocks.sh
```

## Running the API

Start the application:

```bash
go run main.go
```

The API runs on:

```text
http://localhost:8000
```

The root endpoint `/` is not defined, so requesting it returns `404`.

## Authentication

Protected endpoints require a JWT generated by **traney-auth**.

Authentication flow:

```text
Client
  │
  │ POST /auth/login
  ▼
traney-auth :8888
  │
  │ JWT
  ▼
Client
  │
  │ Authorization: Bearer <JWT>
  ▼
traney :8000
```

Example:

```bash
curl -X POST http://localhost:8888/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"abc123"}'
```

Then use the returned token:

```bash
curl http://localhost:8000/clients \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

## API

### Clients

```http
GET /clients
```

Returns the clients accessible to the authenticated user.

The endpoint requires a valid JWT.

Example:

```bash
curl http://localhost:8000/clients \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

## Error handling

Application errors are represented through the project's `AppException` mechanism.

HTTP handlers translate application errors into appropriate HTTP responses instead of silently ignoring service/repository errors.

For example:

* `401` — authentication/authorization error
* `404` — resource not found
* `500` — unexpected server/database error
